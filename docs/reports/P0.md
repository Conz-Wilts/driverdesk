## What surprised us

- **Standard CEL has no bitwise operators** and errors on integer overflow — driver maths needs a DriverDesk function library (`shl`, `band`, `sign_extend`, `le16`, …). The BME280 datasheet's worked example (25.08 °C) is reproduced exactly in a unit test.
- **YAML 1.1 vs 1.2**: PyYAML read the trigger key `on:` as `true`. We renamed vocabulary (`trigger`, `unbound`, `enabled`) and added `DD-L027`/`DD-L028` so descriptions mean the same to every parser.
- **The linter found real mistakes in our own examples** (a renamed LED argument, a `reads_only` command that queues to the device, TMP117/TMP119 ids that a mask made identical).
- **Fuzzing beat proptest**: a mutated `repeat.count: 0` reached unchecked arithmetic in lints that run on schema-invalid input (D-001).
- **Windows main-thread stack is 1 MiB**: debug validation needs ~1 MiB (D-002); `dd`/`xtask` now validate on an 8 MiB thread.
- **Vendor sites block automated datasheet downloads** (analog.com, st.com, nxp.com), skewing the benchmark toward TI and Bosch.

## Debt created

- Library users must give validation ≥ 2 MiB of stack until frame sizes are reduced (D-002) — **P1.T0** (runtime) and P3 (Python binding).
- Benchmark vendor skew (25 TI / 10 Bosch; no ADI, ST, NXP) — revisit with a browser-based fetcher in **P3.T0**.
- Error page DD-L025 now defines "idempotent"; re-run the persona loop whenever diagnostic text changes (procedure in P0-persona.md).
- Domain `driverdesk.dev` used in schema `$id`s and docs links is provisional (ids are URIs only) — decide at R1.
- `cargo-fuzz` nightly workflow runs only once the workflow exists on `main` (this merge).
